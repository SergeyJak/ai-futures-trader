# Public execution-research data collectors

User delegated implementation choices and requested a complete deployable PR. Goal: collect public data needed to evaluate funding, spread, liquidity and adverse execution assumptions for BTC/ETH/SOL research. No orders, private API keys, account fee inference or changes to strategy behavior.

Architecture: an independent Bybit public-linear WebSocket subscribes to `orderbook.50`, `publicTrade`, and `tickers` for each configured market symbol. Pure state handlers maintain a validated local book, deduplicate trades and collect bounded aggregates. Sample quotes/depth/mark prices every 10 seconds; aggregate trades in 10-second event-time buckets with 30-second lateness allowance. Store only aggregates and sample provenance, not unbounded raw tick streams. A separate public REST collector ingests funding settlements, requesting up to 120 days to cover historical strategy research, bounded to five pages per symbol and 200 records per page, with a 10-minute polling interval and 1-hour cooldown on 403/429. Truncated/provider-limited windows are explicitly incomplete.

Storage: `research_market_samples`, `research_trade_buckets`, `research_funding_rates`, plus persisted collector status. Samples/trades retain seven days by default; funding retains 730 days. Hourly cleanup deletes at most 5,000 expired rows per table per run using indexed time columns. All inserts idempotent. Historical missing observations remain missing; there is no forward fill, assumed zero funding or synthetic depth.

Orderbook invariants: require snapshot before delta, reset on reconnect and server restart/update ID 1, reject regressing update/sequence IDs without treating nonconsecutive IDs as proven loss. Bybit update IDs need not increment by one. Apply size-zero removals and positive finite replacements; reject crossed/empty books as observations. A disconnect invalidates the local book until a new snapshot. Freshness is <=30 seconds. Server and local timestamps are retained; stale/missing ticker fields are null.

Trade invariants: validate symbol/side/time/price/quantity, deduplicate bounded IDs, never persist a partial retry as additive volume. Finalize each bucket only after 30 seconds; drop and count later arrivals. Record stream continuity as an observation-quality flag, not a guarantee of complete exchange history. Reconnects invalidate continuity. Keep memory bounded and cap persistence backlog; surface drops/errors instead of blocking the existing candle collector.

Ticker fields: mark/index price, open interest, indicative funding rate and next funding time. Delta fields carry only while fresh in the same connection; reconnect clears state. Historical funding rates are settlement records, not proof of a simulated account's exact cash payment. Rates plus sampled mark prices support estimates with explicitly measured temporal coverage.

Configuration: public research collection enabled by default, opt-out `RESEARCH_DATA_ENABLED=false`; one socket, three topics/symbol. Fees in the data-quality endpoint are explicitly configured assumptions, default taker 0.0006 and maker 0.0002; no claim to know account/VIP rates. `RESEARCH_DATA_RETENTION_DAYS` defaults to 7, integer 1..30. Funding history interval defaults to 30 days; hard bounds prevent runaway pagination. No new dependency.

Read APIs: `/api/research-data` returns collector state, per-symbol coverage/counts/latest observations and explicit limitations; bounded funding and sample history endpoints return requested symbols/time ranges only (max 31 days funding, 24 hours samples, 1,500 rows). Read endpoints never initiate collection, alter positions or write study results. Startup awaits schema creation, then starts optional research tasks. A dedicated pool uses at most two connections with five-second connection/acquisition and server statement timeouts plus a six-second client query timeout, isolating research persistence from the existing trading/candle pool. Shutdown stops new tasks, drains bounded active persistence/fetch work, closes the research socket and its own pool before application shutdown completes.

Validation: fixture tests for snapshot/delta/restart/reconnect, stale/crossed book, ticker staleness, trade duplicates/out-of-order/late data, bounded dedup memory; funding pagination/repeated pages/range/HTTP errors and cancellation; persistence parameterization/idempotency/retention; runtime subscription, overlap/backlog/shutdown using injected transport, time and fetch. Full TypeScript build and existing suite must pass before PR.
